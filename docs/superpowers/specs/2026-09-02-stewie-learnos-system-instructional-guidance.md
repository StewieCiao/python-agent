# Stewie LearnOS 全系统教学指导总方案

**状态：** 统一教学基线，替代“逐关临时规划”方式  
**适用范围：** Python、LangChain/RAG、LangGraph 三条课程，离线版、桌面版、练习反馈、复习与项目  
**首要交付：** 离线版完整课程内容；桌面版继续复用同一课程源  

## 1. 目标与边界

Stewie LearnOS 面向中文零基础学习者，目标不是让用户背 API，而是让用户沿着“理解 → 预测 → 编码 → 运行 → 诊断 → 复习 → 项目迁移”的闭环，最终独立完成可演示的 Python、RAG 和 Agent 项目。

“Gate”只用于开发团队描述实施里程碑，不是学习者看到的课程单位。学习界面统一使用：

```text
学习路线 Track → 阶段 Stage → 课程 Lesson → 阶段项目 Project
```

课程允许自由浏览，但界面明确显示推荐顺序、先修课和当前建议；不以强制锁关代替教学引导。

本方案负责课程结构、单课写法、练习、判题、反馈、复习、项目和离线交付标准，不重复定义 Electron、密钥串、模型网关等已有技术架构。

## 2. 统一教学原则

1. **一个可观察目标。** 每课只承诺一个主要能力，目标必须能通过代码行为或项目产物验证。
2. **先心智模型，后语法。** 先解释数据、状态或控制流怎样变化，再给语法名称。
3. **展示中间状态。** 示例必须让学习者看见输入、关键中间值和输出，避免把方法链、Runnable 或图执行写成“魔法”。
4. **最小知识桥接。** 课程不得依赖尚未学习的知识；确需提前出现时，只解释本课所需的最小作用，并标出后续系统学习位置。
5. **行为优先判题。** 默认验证真实输入输出、异常、状态与边界；只有题目明确要求某种语法结构时才使用 AST 结构检查。
6. **错误必须可行动。** 反馈必须说明实际结果、期望结果、违反的规则和下一步检查位置，不能只说“答案错误”。
7. **提示逐层揭示。** 提示帮助学习者恢复思路，不直接替他完成题目。
8. **来源决定语义。** Python、LangChain、LangGraph 主线以锁定版本的官方文档为准；视频和高质量开源课程只用于解释与覆盖核对。
9. **项目负责迁移。** 每个阶段项目必须组合多个已学能力，不能只是把单课题目换个变量名。
10. **同源交付。** 桌面、浏览器开发版和离线 HTML 都从 `app/content/catalog.ts` 的作者目录生成，不维护平行课程正文。

## 3. 学习闭环

每节非项目课都采用同一个八步闭环：

```text
Learn 学概念
  → Trace 跟踪数据流
  → Predict 先预测结果
  → Code 完成任务
  → Run 真实运行
  → Diagnose 根据反馈修正
  → Review 记录错误模式
  → Transfer 做一个变化题
```

界面不必新增八个页面；八步由现有三张讲解卡、题目、编辑器、判题反馈、提示、答案和复习入口共同完成。

### 三张讲解卡固定职责

1. **概念入门：** 使用生活语言建立心智模型，给出最小示例，说明“它解决什么问题”。
2. **逐步拆解：** 用一个贯穿示例展示输入、每一步中间状态和最终输出，并加入一个“运行前先猜结果”的问题。
3. **常见误区：** 对照至少三类真实错误，解释错误结果与修正检查点；不能只列语法禁忌。

## 4. 三条课程总地图

### 4.1 Python：8 阶段，至少 64 节，6 个渐进项目

| 阶段 | 建议节数 | 核心能力 | 阶段产物 |
|---|---:|---|---|
| P1 运行与数据 | 7 | 运行模型、输出、变量、类型、表达式、输入与格式化 | 可观察的小程序 |
| P2 控制流与容器 | 9 | 分支、循环、字符串、列表、字典、集合、推导式、边界 | 文本数据清理器（项目 1） |
| P3 函数与文件 | 8 | 函数、参数、返回值、作用域、模块、异常、文件、JSON | 命令行任务/账单工具（项目 2） |
| P4 Python 抽象 | 8 | 类、组合、迭代器、生成器、装饰器、上下文管理器 | 可复用组件 |
| P5 工程能力 | 9 | 测试、类型、日志、配置、HTTP、SQLite、包结构、错误边界 | 本地数据服务（项目 3） |
| P6 Agent 核心范式 | 7 | Prompt 数据、工具注册、Action 解析、ReAct、调用边界 | 旅行工具 Agent（项目 4） |
| P7 Agent 系统能力 | 7 | 规划、反思、记忆检索、评估、多 Agent 交接 | DeepResearch 助手（项目 5） |
| P8 生产整合 | 9 | 配置、安全、观测、恢复、测试、文档与演示 | Mini Agent 框架（项目 6） |

Python 路线先保证语言和工程能力，再进入 Agent。函数、异常、模块、HTTP 等知识不得首次出现在 Agent 课中。

### 4.2 LangChain/RAG：7 阶段，至少 48 节，4 个项目

| 阶段 | 建议节数 | 核心能力 | 项目节点 |
|---|---:|---|---|
| L1 模型与结构化交互 | 6 | model、messages、prompt、结构化输出、成本与失败 | — |
| L2 Runnable 数据流 | 7 | LCEL、parser、异步、streaming、批处理、错误边界 | — |
| L3 文档摄取 | 7 | Document、loader、metadata、切分、清洗、可追踪性 | 最小文档问答（项目 1） |
| L4 检索基础 | 8 | embedding、vector store、相似度、检索、两阶段 RAG | 带引用个人知识库（项目 2） |
| L5 检索质量 | 7 | rerank、hybrid、阈值、引用、固定样本评测 | RAG 质量工作台（项目 3 的基础） |
| L6 Agent 与记忆 | 7 | v1 agent、tools、middleware、短期/长期记忆 | Agentic RAG 路由器（项目 3） |
| L7 系统整合 | 6 | 安全、成本、观测、对话式/Agentic RAG、回归评测 | 学习资料研究助手（项目 4） |

LangChain 主线只使用锁定版本的当前语义。旧 `ConversationBufferMemory`、`ConversationChain` 等仅能出现在迁移卡中，不得作为推荐实现。

### 4.3 LangGraph：7 阶段，至少 42 节，4 个项目

| 阶段 | 建议节数 | 核心能力 | 项目节点 |
|---|---:|---|---|
| G1 图与状态 | 6 | StateGraph、State、Node、Edge、compile、invoke | — |
| G2 路由与循环 | 6 | reducer、条件边、循环、结束条件、错误路由 | — |
| G3 持久化 | 6 | checkpoint、thread_id、短期记忆、恢复 | 可恢复审批流（项目 1） |
| G4 长期记忆 | 6 | Store、namespace、key、跨线程记忆 | — |
| G5 人在回路 | 6 | streaming、interrupt、人工确认、恢复 | 带记忆学习导师（项目 2） |
| G6 组合与并行 | 6 | 子图、并行、Map-Reduce、runtime context、观测 | 多步骤研究图（项目 3） |
| G7 综合系统 | 6 | supervisor、RAG、评测、部署边界 | Supervisor + RAG（项目 4） |

所有循环都必须教会终止条件、步数上限和失败状态；所有记忆课都必须区分 thread 内状态与跨 thread 存储。

## 5. 单课作者规范

首版不为了写课程而扩展 UI。优先使用现有 `CourseLesson` 字段表达完整教学：

| 字段 | 写作要求 |
|---|---|
| `title` | 具体动作或能力，避免只写 API 名称 |
| `summary` | 一句可验证学习目标，以“能……”描述 |
| `minutes` | Python 基础 15–25；工程/框架 25–45；项目 60–120 |
| `prerequisites` | 只列真实必需 lesson id；必须无环且都早于本课 |
| `difficulty` | 依据认知负担，不依据课程序号机械生成 |
| `tags` | 主题、能力、错误类型或项目关联；不只保存 track id |
| `guide` | 正好三段，顺序固定为概念入门、逐步拆解、常见误区 |
| `officialSources` | 至少一个直接对应本课语义的官方页面，并记录核验日期 |
| `migrations` | 涉及旧 API 才出现，必须同时给旧写法、新写法与官方依据 |
| `projectLinks` | 指向真正使用本课能力的项目 |
| `exercise.prompt` | 包含背景、输入、期望输出、约束、自查边界；不泄露答案 |
| `starterCode` | 只提供必要签名、测试夹具或 TODO，不提前完成核心步骤 |
| `hints` | 正好三层：概念定位 → 数据流/结构 → 接近解法但不出现完整答案 |
| `solution` | 必须通过全部检查，默认折叠，并说明关键选择与等价写法 |
| `browserChecks` | 至少两个行为检查；边界/异常另设检查；结构检查仅在必要时使用 |

### 内容长度与示例约束

- 每张讲解卡正文建议 80–180 个中文字符，阅读要点 3–5 条。
- 基础示例优先控制在 5–15 行；框架示例不超过 30 行，超出时拆课。
- 示例必须可独立理解，变量名表达业务含义，不使用 `foo`、`bar` 作为主线示例。
- 一课只引入 1 个主概念，最多 2 个紧密相连的辅助概念。
- 正文不得直接出现练习的完整解答行；示例必须与练习同能力、不同数据或场景。

## 6. 练习、提示与判题规范

### 6.1 练习梯度

每个阶段按以下梯度安排，不把所有课程都写成“补全一个函数”：

1. **预测：** 先判断输出或状态变化。
2. **补全：** 在小骨架中完成核心一步。
3. **改写：** 把示例迁移到新数据或边界。
4. **排错：** 修复一个真实且可解释的错误。
5. **整合：** 在阶段项目中组合多个能力。

### 6.2 判题标准

- 正确的等价实现必须通过，不强迫固定变量名、空格或唯一写法。
- 行为检查至少覆盖：典型输入、不同输入、边界或异常。
- 需要检查输出时区分返回值与标准输出；不能让 `print` 冒充 `return`。
- 需要检查数据结构时比较真实值和类型，不依赖源码字符串包含关系。
- RAG 检查必须覆盖来源 metadata、无结果状态和固定小样本质量，不以主观观感通过。
- LangGraph 检查必须覆盖状态合并、终止、恢复和 thread 隔离。

### 6.3 错误反馈合同

每个失败结果对学习者显示四项：

```text
实际：程序真实返回、输出、异常或状态
期望：本检查要求的结果
规则：本课正在验证的行为
下一步：建议检查的概念或代码位置
```

错误模式使用确定性代码记录，例如：`syntax-error`、`name-error`、`type-error`、`boundary-error`、`wrong-return`、`unexpected-output`、`hard-coded-result`、`state-mutation`、`missing-termination`、`missing-citation`。模型可以把真实错误翻译成更易懂的说明，但不能改变判题结果或伪造通过。

## 7. 复习与个性化指导

- 首次失败：优先显示真实反馈，不自动弹答案。
- 同一错误第二次出现：推荐第一层提示和对应讲解卡。
- 连续失败：依次开放第二、第三层提示；答案仍由用户主动展开。
- 通过后：安排一个改变输入、限制或上下文的迁移题，不重复原题。
- 复习队列解释“为什么推荐”：最近错误模式、掌握度、距上次练习时间。
- 个性化题必须先通过可信 exercise family 验证，未通过时明确报告“未生成可验证题目”。
- 学习建议不能用模型自由判断替代实际 attempt、check 和 mastery 数据。

## 8. 项目教学规范

每个项目必须包含：

1. 用户故事和可演示场景。
2. 明确输入、输出、失败状态和不做什么。
3. 里程碑拆分，每个里程碑可独立运行。
4. 固定样例、边界样例与回归测试。
5. README：运行方式、架构图、关键取舍、限制和演示脚本。
6. 复盘问题：哪里用了哪些课程能力，遇到什么错误，下一版如何改进。
7. 可展示成果：截图、终端记录或短演示，不把“代码存在”当成项目完成。

项目验收优先检查可靠性、可解释性、错误边界和可复现运行，不以代码行数评价。

## 9. 离线版优先交付规范

离线版是第一内容验收面，必须：

- 包含三条路线的课程地图、讲解、题目、分层提示、折叠答案、来源文字和迁移卡。
- 不联网、不执行模型、不包含 API Key、聊天、RAG runtime 或桌面桥。
- 保留本地草稿和完成进度，不迁移或清除已有数据。
- 桌面与窄屏都能阅读长文和代码，代码块不挤压正文。
- 提示和答案默认折叠；学习者必须主动逐层展开。
- 每次作者目录变更后由生成流程重建，内嵌课程 JSON 与作者源一致。

离线版内容通过后，再验证桌面端真实执行、错题、个性化和模型辅助；不得为了桌面功能另复制一套课程文字。

## 10. 内容质量门槛

每课必须同时通过以下十项，不能用总分平均掩盖缺项：

1. 目标可观察。
2. 先修关系正确。
3. 三张讲解卡职责完整。
4. 示例展示中间状态。
5. 练习不泄露答案。
6. 三层提示逐步增加信息。
7. 参考答案通过全部检查。
8. 判题接受合理等价解并拒绝伪通过。
9. 来源、版本和迁移信息准确。
10. 离线快照与界面可读。

阶段只有在所有课程通过十项检查、阶段项目可演示、离线版可浏览时才算完成。

## 11. 当前基线需要先纠正的问题

执行本方案时先处理以下已确认缺口：

- 当前作者目录只有 Python 25 节、LangChain/RAG 7 节、LangGraph 7 节，距离 64/48/42 的目标仍远。
- `learningCatalog.ts` 与适配器仍形成过渡作者路径；适配器把每课变成一个阶段、清空先修关系、统一生成一个提示、清空检查和项目信息，不符合本方案。
- 当前未提交的三节 LangChain 草稿直接写入旧目录，其中把官方文档 URL 填入视频资源，已触发视频域名校验失败；不得原样提交。
- LangChain/LangGraph 现有内容普遍只有两张讲解卡、一个泛化提示和零行为检查，必须按统一模板重构。
- 课程版本常量与锁定运行时存在旧值，所有主线示例和迁移卡必须统一到作者目录锁定版本。
- 现有测试只保证“字段存在”，需要补充教学合同、先修图、项目数、提示梯度、行为检查和离线一致性测试。

## 12. 决策记录

采用“统一模板 + 全量课程地图 + 阶段批量落地”。不采用一次性批量生成全部正文，因为容易形成重复、浅层内容；也不采用三条路线各自设计模板，因为会让学习体验、判题和反馈不一致。

执行过程中无需向用户逐关确认。只有涉及改变三条路线目标规模、删减项目、引入付费/联网依赖、改变隐私边界或破坏已有进度格式时，才停止并请求新的产品决策。
