# Agentic RAG Router

一个带约束的 Agentic RAG 路由器：根据问题选择检索工具或直接回答路径，只有检索到真实来源时才生成答案，并保留每次工具调用轨迹。

## 用户故事

作为团队知识库使用者，我希望复杂问题先经过检索工具，回答带可点击来源；资料不足时明确显示“资料不足”，而不是让 Agent 凭空补全。每次路由都能复盘，方便定位是工具、检索还是生成环节出错。

## 输入与输出

- 输入：问题、已注册工具、检索结果和来源 metadata。
- 输出：路由决策、工具调用记录、答案、来源和失败状态。
- 不做：不允许未知工具、不把空召回交给模型、不把模型文本当作引用证明。

## 演示脚本

1. 注册 `search_knowledge` 工具，输入“退款期限”，确认 Agent 记录工具名、参数和真实观察结果。
2. 对命中结果生成带 `source` 的回答，检查引用与召回文档一致。
3. 对没有命中的问题验证 `status=no_results`、答案为“资料不足”，且生成步骤未执行。
4. 传入未知工具名，确认保留 `KeyError` 和失败阶段，不选择默认工具。
5. 用固定问题集运行一次回归，比较工具调用次数、引用覆盖和耗时。

## 架构与验收

`route → tool_call → retrieve → threshold → cite → answer` 每一步都输出结构化事件。验收覆盖工具参数、未知工具、命中来源、重复来源去重、无资料边界和上游模型失败；API Key 仅由桌面版本地安全服务提供。

## 已知限制

- 示例检索器使用本地小数据集，不能代表生产知识库召回质量。
- Agent 路由规则是确定性的，复杂规划需要后续评测和人工审查。
- 离线 HTML 不包含模型调用或 RAG runtime；真实运行需要桌面完整版。
