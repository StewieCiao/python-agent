# 可恢复研究工作流 Agent

## 用户故事

研究任务按“规划 → 检索 → 摘要 → 事实核对 → 人工确认 → 成稿”推进。任意节点失败或需要确认时，学习者可以查看状态并从同一个 `thread_id` 恢复，而不会混入另一个任务的数据。

## 架构与数据流

`StateGraph → 条件路由 → 检索节点 → 证据节点 → interrupt → checkpoint resume`

短期执行状态保存在 thread checkpoint；跨会话偏好放入 Store，二者不混用。每个循环有业务完成条件和最大步数，拒绝或失败会保留明确状态。

## 演示脚本

1. 用 `thread_id=research-a` 启动任务，展示节点更新。
2. 在人工确认节点中断，关闭并重新打开任务。
3. 使用同一 thread 恢复并完成成稿。
4. 用 `research-b` 并行启动，验证状态彼此隔离。
5. 注入一个失败检索节点，展示真实错误和可恢复位置。

## 已知限制

示例默认使用确定性小数据集；真实网络检索、权限审批和生产级并发需要在部署环境中另行配置。
